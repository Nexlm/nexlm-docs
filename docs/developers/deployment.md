# Deployment

Recommended setup: **API + PostgreSQL on Render** (or Railway) and the **client on Vercel**.

## API on Render

The repository includes `render.yaml`:

| Setting | Value |
| --- | --- |
| Build | `npm ci && npm run db:generate -w server` |
| Pre-deploy | `npm run db:deploy -w server` |
| Start | `npm start -w server` |
| Health check | `/health` |
| Database | Render PostgreSQL, wired to `DATABASE_URL` |

Set these secrets in the dashboard:

- `ENCRYPTION_KEY` — generate once and **back it up securely**
- `PLATFORM_SECRET_KEY`
- `CLIENT_URL` — your Vercel URL(s)
- `PUBLIC_API_URL` — the Render service URL
- `CLOUDINARY_URL`, `SMTP_*`, `SMILE_*` as needed

`JWT_SECRET` is generated by the blueprint.

## Client on Vercel

| Setting | Value |
| --- | --- |
| Root directory | `client` |
| Build command | `npm run build` |
| Output | `dist` |
| Env | `VITE_API_URL=https://<your-api>` |

`client/vercel.json` rewrites all routes to `index.html` for client-side routing.

## Going to mainnet

1. Set `STELLAR_NETWORK=public` and `HORIZON_URL=https://horizon.stellar.org`.
2. Use a new `PLATFORM_SECRET_KEY` generated offline and stored in a secrets manager.
3. Configure Smile ID production credentials and set `SMILE_ENV=production`.
4. Configure Cloudinary — local uploads don't survive redeploys.
5. Review [security model](./security-model) and rate limits.
6. Run the smoke test against a **staging testnet** environment before every release.

::: danger Wallets are network-specific
Testnet user wallets don't exist on mainnet. Launch mainnet with a fresh database.
:::

## Health check

`GET /health` returns `{ "status": "ok", "network": "testnet", "time": "…" }` without touching the database.
